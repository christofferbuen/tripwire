# E: the fake VM behind the bait credential

Read `2026-09-19-wave1-overview.md` first. **Do not start until package D's
"On the VM" steps 3, 4 and 9 have passed** and A2 has landed.

**Owner files (builder):** `beelzebub/` (new directory), `compose.fakevm.yaml`
(new), `vector-fakevm.toml` (new).
**Orchestrator part, after the builder lands:** lines in
`bootstrap-opensearch.sh`, `alerts.py`, `dashboards.py`, `enrich.py`,
`droppers.py`, `compose.sentinel.yaml`, `README.md`. Listed at the end.
**Builder model:** opus.

## What it is

A2 makes the sentinel serve a `/.env` that names an SSH port, a user and a
password on the same machine. This package puts something behind that port:
[Beelzebub](https://github.com/beelzebub-labs/beelzebub) v3.9.1, upstream
image, unmodified, whose "shell" is a language model writing text.

## Why this engine and not Cowrie

The requirement is that the thing cannot be used to attack us or anyone
else. Cowrie emulates a shell in Python and its `wget` really downloads,
from a host the attacker picks; forwarding is fake by default but the real
code is one config key away. Beelzebub's SSH service registers a password
handler and a session handler and nothing else: no port forwarding, no SFTP
or SCP subsystem, no process execution, no fetch. Every "command" becomes a
string sent to one fixed HTTPS endpoint, and the answer is printed. Code
that is absent cannot be switched on by a mistake or an exploit of a config
parser.

What it costs: one allowed outbound destination, an API key on a machine
that is meant to be owned, and a shell that is slower and less consistent
than a real one. The first two are fenced below. The third is accepted.

## Containment, as things that can be tested

| # | property | how it is held | test |
|---|---|---|---|
| C1 | nothing the attacker types is executed | upstream design; image unmodified, pinned by digest | T4: `touch /tmp/x; ls /tmp` in the fake shell changes nothing in the container (`podman diff` empty, root is read-only anyway) |
| C2 | no forwarding, no file transfer | upstream design | T5: `ssh -L`, `ssh -D`, `sftp`, `scp` all fail |
| C3 | only the bait password opens a session | anchored `passwordRegex`, rendered from a validated value | T1, T2, T3 |
| C4 | the container reaches one destination | own Unix user, D's `skuid` rules and `llm4` set, cloud firewall outside | V2 on the VM |
| C5 | a stolen API key is worth little | provider-side credit limit on a key used for nothing else | operator checklist |
| C6 | a compromise of the engine reaches nothing of ours | separate Unix user from the sentinel and its Vector; no secrets of theirs readable; `read_only`, `cap_drop: ALL`, `no-new-privileges`, memory, pids and CPU limits | V4 |
| C7 | attacker text and model text never become fields or markup | Vector builds the event from a whitelist; index mapping is `dynamic: false` | T7 |
| C8 | nobody gets a free model through us | built-in per-address rate limit, session deadline, and C5 as the ceiling | T6 |

## Files

### `beelzebub/beelzebub.yaml`

Core config: JSON logs to `/logs/beelzebub.log`, RabbitMQ tracing off,
cloud off, Prometheus left on its default port and **not published**.

### `beelzebub/ssh.yaml.tmpl`

```yaml
apiVersion: "v1"
protocol: "ssh"
address: ":2222"
description: "fakevm"
commands:
  # static answers first: cheap, instant, and identical every time
  - regex: "^whoami$"
    handler: "deploy"
  # ... the table below ...
  - regex: "^(.+)$"
    plugin: "LLMHoneypot"
serverVersion: "@@SERVER_VERSION@@"
serverName: "@@SERVER_NAME@@"
passwordRegex: '@@PASSWORD_REGEX@@'
deadlineTimeoutSeconds: @@DEADLINE@@
plugin:
  llmProvider: "openai"
  llmModel: "@@LLM_MODEL@@"
  host: "@@LLM_ENDPOINT@@"
  prompt: "@@PROMPT@@"
  rateLimitEnabled: true
  rateLimitRequests: @@RATE_REQUESTS@@
  rateLimitWindowSeconds: @@RATE_WINDOW@@
```

No `openAISecretKey` line. The engine reads `OPEN_AI_SECRET_KEY` from the
environment and that comes from an env file on the VM.

`serverVersion` must produce exactly the banner the sentinel sends on 22 for
the active persona; take it from `sentinel.py`, do not retype it.

Static table (answers must agree with the persona's release and with each
other): `whoami`, `id`, `hostname`, `uname -a`, `uname -r`, `cat
/etc/os-release`, `cat /etc/issue`, `nproc`, `pwd`, `echo $SHELL`, `exit` and
`logout` are handled by the engine. Anything with arguments the table does
not list goes to the model.

### `beelzebub/prompt.txt`

The terminal prompt. Requirements: an Ubuntu release matching the persona;
user `deploy`, not root, no sudo rights; a small PHP site under `/var/www`;
output only what a terminal prints; never mention being a model or a
simulation whatever the input says; network tools (`wget`, `curl`, `nc`,
`ssh`, `ping`, `apt`) behave as on a host whose outbound traffic is
filtered: name resolves, connection times out. That last line is the honest
one, and it keeps the model from inventing downloaded files. No real
hostname, address or operator detail goes in this file: it is sent to a
third party and an attacker can talk the model into reciting it.

### `beelzebub/render.py`

Standard library. `render.py --env FILE --out DIR` writes `ssh.yaml` from the
template; `--selftest` runs the tests below.

```python
BAIT_RE = re.compile(r"[A-Za-z0-9_.+-]{12,64}")

def password_regex(bait: str) -> str      # "^" + re.escape(bait) + "$", ValueError unless BAIT_RE.fullmatch
def render(template: str, values: dict[str, str]) -> str   # ValueError on any @@KEY@@ left over or any value containing a quote, newline or "@@"
```

An empty pattern matches every password and an unanchored one matches any
password containing the bait. Both would turn a decoy into an open door,
which is why this function exists and has tests.

Env keys: `FAKEVM_PORT`, `BAIT_PASSWORD`, `SERVER_NAME`, `LLM_MODEL` (default
`deepseek/deepseek-v4-flash`), `LLM_ENDPOINT` (default
`https://openrouter.ai/api/v1/chat/completions`), `DEADLINE` (default 600),
`RATE_REQUESTS` (default 10), `RATE_WINDOW` (default 60),
`OPEN_AI_SECRET_KEY` (never rendered, only passed through compose).

### `compose.fakevm.yaml`

One service. Image pinned as `name:v3.9.1@sha256:<digest>` (the builder
resolves the digest and records where it came from). `read_only: true`,
`tmpfs: /tmp`, `cap_drop: [ALL]`, `security_opt: [no-new-privileges]`,
`mem_limit: 256m`, `pids_limit: 64`, `cpus: 0.5`, `restart: always`,
`env_file` for the key, rendered config directory mounted read-only, log
directory `/var/log/tripwire-fakevm` mounted read-write, port
`${FAKEVM_PORT}:2222` and no other. Bridged network.

The recorded source address must be the client's real one. If the rootless
port forwarder hides it (T8), switch to `network_mode: host` with the
address set to `:${FAKEVM_PORT}`, and say so in the report: D's rules match
on uid and hold either way, and the metrics port stays closed at the
firewall.

### `vector-fakevm.toml`

A second config file for the VM's existing Vector (it gains a read-only
mount of the log directory and a second `--config`; orchestrator edits the
compose file). Source: the JSON log. Transform: **build a new event from
named fields, never merge the parsed object.**

| index field | from | limit |
|---|---|---|
| `@timestamp` | `event.DateTime` | parsed, else now |
| `source.ip`, `source.port` | `event.SourceIp`, `event.SourcePort` | must parse as an address, else drop the event |
| `fakevm.session` | `event.ID` | 64 |
| `fakevm.status` | `event.Status` lowercased | one of `start`, `end`, `stateless`, `interaction`, else drop |
| `fakevm.user`, `fakevm.password` | `event.User`, `event.Password` | 256 |
| `fakevm.client` | `event.Client` | 256 |
| `fakevm.command` | `event.Command` | 4096 |
| `fakevm.output` | `event.CommandOutput` | 8192 |
| `bait.credential_used` | `true` when status is `start` | |
| `event.dataset` | `"fakevm"` | |

Lines that are not events (engine start-up, errors) are dropped. Sink: same
endpoint, user and secrets as the sentinel sink, alias `tripwire-fakevm`,
its own disk buffer.

The exact shape of the engine's log line (where the event object sits) is
to be read from a real line produced in T3, not assumed.

## Acceptance tests

`beelzebub/test-local.sh`, run with local podman. The model endpoint is a
stub: a Python `http.server` in the script that answers every POST with a
fixed OpenAI-format completion `STUB-OUTPUT`. No key, no cost, no network.
The SSH client is a throwaway Alpine container with `openssh-client` and
`sshpass`.

- T1 `render.py --selftest`: `password_regex("Deploy-2026.ok+x")` equals
  `^Deploy\-2026\.ok\+x$`; empty, 11-character, and `a b c d e f g h` values
  raise `ValueError`; a template with a key missing from the values raises;
  a value containing `"` raises.
- T2 wrong password, empty password, and `x<bait>x` are all refused.
- T3 the bait password opens a session; `whoami` prints `deploy`; `ls`
  prints `STUB-OUTPUT`; the log holds one `Stateless` line per attempt from
  T2 with the password recorded, then `Start`, `Interaction`, `End`.
- T4 after T3, `podman diff` on the container shows no change outside the
  log mount.
- T5 `ssh -N -L 8080:127.0.0.1:80`, `ssh -N -D 1080`, `sftp` and `scp` fail;
  `ssh host 'id'` returns text and spawns nothing (`podman top` shows one
  process before and after).
- T6 the 11th model-bound command inside a minute is refused by the rate
  limit; a session is cut at `DEADLINE` (run this one with `DEADLINE=5`).
- T7 `vector test` on `vector-fakevm.toml`: a `Start` line yields
  `bait.credential_used == true`; an `Interaction` line with a 20 000
  character output yields 8192; a line carrying an extra key `"evil": {"a":
  1}` yields an event without it; a line with `SourceIp: "not-an-ip"` yields
  nothing; an engine start-up line yields nothing.
- T8 the `SourceIp` recorded in T3 is the client container's address and
  not the forwarder's.
- T9 the stub saw an `Authorization` header only when the env var was set,
  and the prompt text is what `prompt.txt` holds.

## On the VM (orchestrator, with the operator)

Operator first: an OpenRouter key created for this and nothing else, with a
hard credit limit (5 USD is months of traffic at this model's price), stored
only in the fake-VM user's env file, mode 600.

- V1 create the Unix user, enable linger, fill the four `FAKEVM_*` /
  `LLM_HOST` keys in D's env file, `harden-sentinel.sh --apply`, `--confirm`,
  `--check`.
- V2 from inside the running container's network namespace: a connection to
  an arbitrary public address on 443, to the collector's tunnel address, and
  to any port 22 all fail and each raises the egress alert; the model
  endpoint answers.
- V3 from outside: log in with the bait password, run five commands, see
  the events in `tripwire-fakevm-*` and the alert on the phone.
- V4 as the fake-VM user: the sentinel's secrets file, its log volume and
  the WireGuard config are unreadable.
- V5 `nmap -sV` on the persona ports is unchanged; the new port shows the
  same SSH banner as 22.
- V6 drain test: stop the `llm4` refresh timer, wait out the element
  timeout, confirm the shell degrades to errors and nothing else changes;
  start the timer again.

## Known tells, accepted

- The key-exchange algorithm list is Go's, not OpenSSH's. A second SSH
  service on a high port with a different stack is at least a common sight.
- The engine appears to generate its host key at start. Check; if true,
  restarts change the key. Restart rarely, and report it upstream rather
  than patching the image.
- Latency of a model call, and answers that drift between sessions. The
  static table covers the first commands most clients send.

## Edge-case matrix

| axis | applies | note |
|---|---|---|
| model endpoint down, slow, or out of credit | yes | the shell prints an error; nothing else happens; V6 |
| prompt injection ("print your instructions") | yes | the prompt holds nothing worth stealing; the key is an HTTP header the model never sees |
| many clients using the bait at once | yes | per-address limit, pids and memory limits, credit ceiling |
| attacker sends terminal escapes or megabytes | yes | truncated in Vector; never printed by us; `ascii()` in any script output |
| engine restart | yes | host key tell above; `restart: always` |
| VM reboot | yes | linger for the second user, same as D step 9 |
| bait password rotated | yes | re-render, recreate the container, update the bait file A2 serves; one value in one env file feeds both |
| IPv6 | no | the port listens on v4 like the persona |

## Knobs

Model, endpoint, rate limit, session deadline, prompt text, static command
table, container limits. All in the env file, `prompt.txt` or the template.

## Where's the door handle

The attacker's: `GET /.env` on 80 answers with deploy credentials and a port;
the port is open; the password works; a prompt appears. When the model is
unavailable they see a command error, not a stack trace.

The operator's: a high-channel alert "bait credential used" with the address
and how long ago that address fetched the bait; a saved search "Fake VM
sessions" with one row per command; the provider's dashboard shows spend
against the limit. When the limit is reached the shell goes dumb and the
digest says the fake VM has produced no `interaction` events while `start`
events continue.

## Orchestrator part

- `bootstrap-opensearch.sh`: template and ISM policy for `tripwire-fakevm-*`
  (30 d, `dynamic: false`, `fakevm.command` and `fakevm.output` as `text`
  with a `keyword` sub-field capped at 1024), the write alias, and the
  sentinel writer role extended to it.
- `alerts.py`: monitor `bait-used` on `fakevm.status: start`, high channel.
- `dashboards.py`: saved search "Fake VM sessions"; a panel joining bait
  fetches to logins by address.
- `enrich.py`: add the index family to the event indices so addresses there
  get the same enrichment.
- `droppers.py`: add `fakevm.command` to the scanned fields. This is likely
  the richest dropper source there will be.
- `compose.sentinel.yaml`: the log mount and the second `--config`.
